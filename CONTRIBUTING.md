# Contributing

CoordMesh is in research-first bootstrap. Useful contributions include primary-source standards research, implementation/project comparisons, scenario refinement, documentation, and focused proposals.

## Before proposing protocol behavior

1. Check the [roadmap](docs/roadmap.md), open issues (when a forge is configured), and existing documents.
2. Compare standards and implementations using the [landscape method](standards/landscape.md).
3. Record evidence, date checked, limitations, and uncertainty. Distinguish REUSE, PROFILE, INVENT, and UNKNOWN.
4. For significant architectural changes, submit a Proposed ADR. Do not silently overturn an Accepted ADR.
5. Prefer specification, schema, and conformance tests before implementations where appropriate.

Agents may research, document evidence, refine scenarios, and propose ADRs autonomously. Project-wide architecture, governance, security policy, compatibility commitments, and accepted ADR decisions require maintainer/community review. Never invent cryptography or infer consensus from silence.

Please include source links and describe any assumptions. Avoid speculative backlog expansion.
