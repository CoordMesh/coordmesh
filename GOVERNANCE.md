# Governance

## Bootstrap

OpenCoord currently has a bootstrap maintainer population that may consist of one person. This is an honest temporary operating condition, not evidence of broad consensus or a permanent founder mandate. NOverhead and the original initiator are ordinary bootstrap contributors and have no guaranteed special or permanent authority.

During bootstrap, the maintainer may organize the repository, review contributions, publish releases, and maintain project infrastructure. Significant technical decisions should be documented as ADRs with status and rationale. Seek public review when practical and record dissent or unresolved questions.

## Growth path

The intended path is contributor → trusted contributor → maintainer → multiple maintainers and, if community size warrants it, lightweight project governance or working groups. Criteria and selection processes should be developed with contributors before the project needs them. Do not simulate a community that does not yet exist.

Maintainers should document responsibilities, succession, release production, security response, and infrastructure dependencies as the project grows. Authority should be replaceable and scoped. No person, organization, service, forge, or infrastructure component should become irreplaceable by design.

## Scope

This document describes technical project governance only. No legal entity is assumed or created. Legal custody of assets, if needed later, should remain conceptually separate from technical decision-making.

## Changes

Governance changes require visible proposal and review. The bootstrap maintainer may propose changes but must not represent that proposal as community consensus.
